## 一、开始之前

本文适合第一次编写本站教程的作者。文章顶部的 `+++` 区域是 TOML 格式的页面信息，不属于正文。

- **标题**：修改顶部 `title`，正文通常不再重复一级标题。
- **简介**：修改 `description` 和列表摘要 `summary`。
- **发布**：写作时保持 `draft = true`，发布时改为 `false`。
- **排序**：`weight` 越小越靠前，建议使用 10、20、30。
- **目录**：`showTableOfContents = true` 根据正文标题生成目录。
- **头图**：本示例用 `showHero = false` 关闭文章头图，不影响正文图片。

## 三、插入图片

### 同目录图片

下面这张图片位于本文同目录的 `example-diagram.svg`，仅用于展示图片路径和显示效果：

![教程编写流程：编写正文、放入图片、检查后发布](example-diagram.svg)

*图 1：教程编写流程示意。真实截图建议使用 PNG、JPEG 或 WebP。*

对应的 Markdown 写法：

```markdown
![图片内容说明](example-diagram.svg)

*图 1：图片下方的说明文字。*
```

替换为真实截图时，把 `step-01.png` 复制到本文目录，再使用：

```markdown
![点击多人游戏按钮后的界面](step-01.png)
```

图片说明应描述读者需要关注的内容；发布前检查图片中是否泄露账号、IP、聊天记录或其他敏感信息。

### 需要精确控制宽度时

优先使用上面的标准 Markdown。确实需要限制图片显示宽度时，本站已启用原生 HTML，可参考下面的写法，注意文件必须存在：

```html
<figure style="max-width: 720px; margin: 1.5rem auto;">
  <img src="step-01.png"
       alt="添加服务器窗口"
       loading="lazy"
       style="display: block; width: 100%; height: auto;">
  <figcaption style="text-align: center;">图 2：填写服务器地址。</figcaption>
</figure>
```

原生 HTML 图片不会经过 Markdown 图片渲染钩子的同一套处理逻辑，因此优先使用标准 Markdown，并在网站预览中确认 HTML 效果。
